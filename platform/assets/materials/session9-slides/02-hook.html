THE PROBLEM // REAL LIFE
💥 Your app just crashed.
A user runs your game and enters "banana" where a number should go.
Python panics, prints a wall of red text, and your program dies.
game.py
age = int(input("Enter your age: "))
print("Next year you'll be", age + 1)
 
# user types: banana
Traceback (most recent call last):
  File "game.py", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'banana'
😱 Total disaster?
Real apps face this every single day: bad input, missing files, broken connections. The question is not if your code breaks — it's whether you handle it with grace.
Today: you learn to catch errors, read scary messages, and build programs that never crash on bad input.
